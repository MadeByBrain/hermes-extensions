# Changelog: privacy-xray

## privacy-xray-v1.0.0 (2026-11-06)

First release.

- Flow ledger: `pre_api_request` and `pre_auxiliary_call` record every outgoing model request as metadata (destination host, vendor, vendor HQ country, for aggregators the model's vendor, size, personal data type counts, canary hits by message field). Never content. Messages are scanned newest first under a per-request budget with a content-hash cache, so long histories are cheap and the newest text is always covered; a request that did not fit is marked `incomplete` and map, trace and report say so.
- Detectors: e-mail (without role mailboxes), IBAN (mod 97), payment card (known issuer ranges and Luhn, never digits right after `+`), international phone numbers, public IPv4 only, German Steuer-ID and USt-IdNr (check digits), user watch terms and canary values as whole words. All regexes run in linear time (timing tests on 1,000,000 character adversarial inputs).
- Aggregators (OpenRouter, Vercel AI Gateway, Kilo Code, OpenCode, Hugging Face router, Novita): the model's vendor is read from the model id and shown as "OpenRouter → DeepSeek model"; a side request is an extra recipient when the aggregator or the model's vendor differs from the main route. The final processor behind an aggregator is not visible, and every view says so.
- `/xray canary` and `/xray trace [id] [--deep]`: fictitious person with fake values, traced through requests and local stores (state.db messages, titles, stored system prompts, delivery queue, session files, request dumps, memories, logs, cron output, other plugins' data).
- `/xray check` and `/xray fix <id> [--yes]`: config audit with severity and exact `hermes config set` fix per path, including side task fallback chains, web search with Hermes' keyless fallback (`web.rescue`) and web page reading (`web.extract`); side task routing read from the Hermes source; fixes applied through the public config writer, rolled back step by step if one fails, never automatically. Chat retention is advice only: the plugin never applies a setting that makes Hermes delete chats and shows a clear warning instead.
- `/xray find "<name>" [--export] [--deep]`: read-only subject search with masked snippets (Hermes' full-text indexes, `LIKE` only to confirm), Markdown and JSON access report that says whether the search was complete and, if not, why and which files.
- `/xray map` and `/xray report`: leak map in the chat and as a self-contained HTML file with a verdict headline, a Sankey style flow map (CSS-only moving dots, yellow for the canary, pulsing outline on extra recipients with personal data) and a before/after view of two canaries. Each block names its scope: the verdict card and its chips cover the latest canary only; the flow map, its stats and the personal data bars cover the requests since the latest canary when it is the "after" side of a before/after pair, otherwise the last turns. No scripts, no external assets; animations stop with "reduce motion".
- Dashboard tab "Privacy X-ray" (`dashboard/`): the same leak map live in `hermes dashboard`, polled every 15 seconds, shown in a sandboxed frame.
- Tool `privacy_xray` (map, check, trace, find) and a bundled skill that points the model to it.
- Optional guard (`llm_request` middleware, off by default): masks canary values and watch terms in the human-readable text of main requests; never tool names, ids, tool arguments, JSON keys, thinking blocks or anything signed.
- Safety: `fix --yes` and `find` run only on local surfaces (CLI, TUI, desktop, dashboard) unless `allow_sensitive_on_gateways` is on; unknown surfaces are refused. Plugin data folder 700, every file 600. Friendly usage messages in English and German for wrong arguments.
- Terminal output: in the CLI and TUI, `/xray` text is wrapped at word boundaries with a hanging indent (setting `wrap_width`, 0 = the terminal width when known, else 100), so terminals no longer break words in the middle; command lines and commands in backticks are never split.
- Works on Hermes v0.22.7 and v0.23.0 (tests, `validate`, live CLI run on both; on v0.23 slash commands run in the gateway and the classic CLI reports itself as `local`).
- Texts in English and German (`language: auto | en | de`).
